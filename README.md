# Brandtech E-Commerce Store

A modern e-commerce application built with Next.js 14, TypeScript, Tailwind CSS, and Zustand — featuring an AI-powered shopping assistant backed by a RAG pipeline and a local LLM.

## Features

- **Product Listing** — Responsive grid with server-side filtering
- **Advanced Filters** — Brand, category, price range, color, and size; all state lives in the URL so results are shareable and bookmarkable
- **Product Detail Pages** — Statically generated (SSG) with per-product metadata
- **Shopping Cart** — Add items with size and color selection, managed by Zustand
- **AI Shopping Assistant** — Floating chat widget backed by an agentic LLM loop with tool-calling and RAG (see below)
- **Responsive Design** — Mobile-friendly with Tailwind CSS
- **Type Safety** — Fully typed with TypeScript
- **E2E Tests** — Playwright smoke tests covering the storefront, product pages, and the chat widget

## AI Architecture

The chat feature is more than a simple chatbot. It runs an **agentic tool-calling loop** against a local LLM (Ollama + `llama3.2`) and retrieves grounded context via **RAG** before answering.

```
User message
    │
    ▼
POST /api/chat  (Next.js App Router streaming route)
    │
    ├─ System prompt with strict grounding rules
    │
    ▼
Ollama (llama3.2) ◄─── tool definitions (searchFAQ, searchProducts, checkStock)
    │
    ├─ tool_calls in response?
    │       │
    │       ├─ searchFAQ       → Vectra vector store (nomic-embed-text embeddings)
    │       ├─ searchProducts  → products.json (filters: brand, color, price, size …)
    │       └─ checkStock      → products.json (by product ID)
    │
    ├─ feed tool results back → loop (max 5 iterations)
    │
    └─ no more tool calls → stream final answer to UI
```

### Key files

| Path | Purpose |
|------|---------|
| `src/app/api/chat/route.ts` | Streaming POST handler; runs the agentic harness loop |
| `src/lib/agentTools.ts` | Tool definitions + implementations (`searchFAQ`, `searchProducts`, `checkStock`) |
| `src/components/ChatWidget.tsx` | Floating chat UI; renders markdown (images + links) with `react-markdown` |
| `scripts/ingest.ts` | One-off ingestion script — chunks FAQ data and writes embeddings to the Vectra index |
| `scripts/faq_data.json` | Source FAQ content |
| `rag_index/` | Vectra local vector index (generated by the ingestion script, not committed) |

### RAG — Retrieval-Augmented Generation

FAQ content is embedded offline with `nomic-embed-text` (via Ollama) and stored in a local [Vectra](https://github.com/Stevenic/vectra) vector index. At query time `searchFAQ` embeds the user's question with the same model and returns the top-4 semantically similar FAQ chunks.

### Grounding rules

The system prompt explicitly forbids the LLM from inventing product URLs, names, or prices. Everything shown in the chat must come from a tool result — the LLM is only allowed to format and explain what the tools return.

## Getting Started

### Prerequisites

- Node.js 18+
- [Ollama](https://ollama.com) installed and running locally
- Both models pulled:

```bash
ollama pull llama3.2
ollama pull nomic-embed-text
```

### 1. Install dependencies

```bash
npm install
```

### 2. Build the RAG index (one-off)

```bash
npx ts-node --project tsconfig.scripts.json scripts/ingest.ts
```

This reads `scripts/faq_data.json`, embeds each chunk with `nomic-embed-text`, and writes the Vectra index to `rag_index/`.

### 3. Run the dev server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The chat button (💬) is in the bottom-right corner.

### 4. Run E2E tests

```bash
npx playwright test
```

Tests cover: storefront rendering, product detail navigation, and chat widget opening. Results print to the terminal — no HTML report is generated.

## Environment Variables

Create a `.env.local` file for any overrides (never commit this file):

```
# Example — override the Ollama base URL if it's not on localhost
OLLAMA_BASE_URL=http://localhost:11434
```

## Rendering Model

Pages are React Server Components by default; only interactive leaves are client components. `products.json` is read on the server and never bundled into the client JS.

- `/` — dynamically rendered; filtering runs server-side so filtered URLs are shareable
- `/product/[id]` — statically generated via `generateStaticParams`; unknown IDs return HTTP 404
